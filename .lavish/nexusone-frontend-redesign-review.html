NexusOne frontend redesign

Move from demo shell to authenticated work app.

The current interface starts directly in chat with a role selector. The target product should start with a controlled demo login, land users in a conversation workspace, and let them switch between prior chats without losing role context, sources, tickets, or feedback state.

Grilling questions

Answer these before implementation so the frontend does not drift again.

  • 1. Is login a fake demo selector or a real credential flow? Recommended for this project: fake demo login with profile cards, because backend auth is not in scope yet.
  • 2. Should conversations persist across page refresh? Recommended: yes, use localStorage first; DB persistence can come after the UX is accepted.
  • 3. Are conversations scoped per user profile? Recommended: yes. Switching from employee to CEO should not show the employee's prior chat thread.
  • 4. What should the default post-login screen be? Recommended: latest conversation if it exists, otherwise a blank new chat with suggested tasks.
  • 5. Where should citations, tickets, and trace live? Recommended: right context panel on desktop; collapsible details below messages on mobile.
  • 6. Are we allowed to keep the role-switcher after login? My recommendation: only expose it through a demo account menu, because a permanent role selector makes the app feel fake.
